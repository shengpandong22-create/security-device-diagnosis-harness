# 三分钟项目介绍

## 0:00—0:30：问题与定位

“我做的是一个可信安防设备诊断 Agent Harness。场景包括摄像头黑屏、录像缺失、门禁刷卡异常和报警误报。
重点不是做一个能调用模型和工具的 Demo，而是解决模型选错工具、伪造证据、越权操作、结论不可追溯以及版本
效果无法比较的问题。”

## 0:30—1:20：核心闭环

“请求进入 Application Service 后，ToolLoopRunner 让模型在 allowlist 内选择只读工具；所有调用必须经过
ToolRegistry，再由 RoutedDeviceGateway 根据资产、能力和 Adapter 状态路由。成功结果转成 Evidence，失败只保留
受控错误，不伪造 Evidence。模型只能产生 possible/probable 候选，CitationPolicy 检查引用归属和证据强度，
最终 confirmed 只能由 HumanReview 推进。”

## 1:20—2:05：工程可信性

“数据层通过 Repository Port 隔离 SQLAlchemy，使用 Alembic、深层脱敏和 CAS 乐观锁；冲突返回 409，不自动
重跑 Agent 或人工动作。系统还有追加式审计、一致性扫描和 SQLite 备份恢复。知识侧把人工确认诊断沉淀为
KnowledgeCandidate，只有 confirmed 知识能被 Keyword/BGE/Hybrid 检索，避免错误知识反馈污染。”

## 2:05—2:40：评测与设备验证

“评测使用版本化 Dev/Validation/Test 数据集，分别评分标签、工具选择、Evidence 合规、工作流、延迟和成本，
并支持失败归因、历史对比和 Release Gate。Static/Fake、Simulator、真实模型和授权真机的结果严格分开。
设备侧先用 ONVIF simulator、Toxiproxy 和 FastAPI 契约服务覆盖异常，最后在一台授权 Wi-Fi 摄像头上完成
WS-Discovery、HTTP Digest、Profiles、Stream URI 和 RTSP Digest OPTIONS 的最小只读闭环。”

## 2:40—3:00：边界与价值

“这个项目没有宣称生产上线或多厂商兼容。它证明的是：我能把不确定的 Agent 行为放进确定的权限、证据、状态、
并发和评测边界，并用可复现证据说明哪些能力已验证、哪些仍未验证。”

## 讲述提醒

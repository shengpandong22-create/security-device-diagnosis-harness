# 诚实边界与防包装过度

## 可说 / 不可说

| 主题 | 可以说 | 不可以说 |
| --- | --- | --- |
| 上线 | 完成工程化封版与授权试接入 | 已在公司生产上线 |
| 真机 | 一台授权 Wi-Fi 摄像头完成最小只读协议闭环 | 已完成多品牌兼容 |
| 模型 | DeepSeek 固定 Validation 案例结构化评测成功 | 线上准确率 100% |
| RAG | 建立 confirmed-only 与三路检索基线 | RAG 显著提升所有场景 |
| 并发 | CAS 检测 stale update | 系统完全并发安全 |
| 安全 | 有只读、授权、预算、脱敏和审计约束 | 达到某安全认证/绝对安全 |
| Simulator | 可重复覆盖协议/网络/业务异常 | 等价真实设备群 |
| AI 协作 | 使用 AI 辅助开发并负责设计审计验收 | 全部纯手写或 AI 自动完成 |

## 遇到不知道的问题

使用三步回答：

1. 明确当前事实：“这个项目没有验证多实例 SQLite。”
2. 给出分析维度：“我会关注锁、隔离级别、共享文件系统和故障恢复。”
3. 给出验证方法：“用 PostgreSQL 替换 Adapter，设计并发与故障注入基线，而不是直接宣称可用。”

## 数字表达规则

- 报告样本分母：说“2/2 Validation cases”，不要只说 100%。
- 区分测得 0 与不可得 `null`。
- 测试数量只能证明回归覆盖，不能直接证明业务正确。
- 延迟、token、准确率必须带环境、模型、数据集版本和日期。
- 没有数据就说不可得，不估算。

## 项目所有权的证明方式

不是背诵所有文件，而是能：

- 画出六条链；
- 解释一次失败到修复的因果；
- 指出一个替代方案及取舍；
- 说出证据强度和未验证边界；
- 在源码中迅速定位关键不变量和测试。

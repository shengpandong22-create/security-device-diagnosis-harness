# Phase 7 诊断质量评测体系实施规格

## 1. 目标

建立可重复、可比较、可追溯的 Agent 质量评测体系，使功能、Prompt、规则、工具和检索策略的修改都必须经过数据证明。

## 2. Phase 7A：数据集协议

- `dev`：日常快速反馈，允许开发者查看标签；
- `validation`：版本选择和阈值调整，不用于直接编写个案规则；
- `test`：最终发布门禁，避免被开发过程污染；
- 每个案例包含输入事实、允许工具、期望候选、必要证据类型、禁止行为和预算；
- 同一业务模板派生的数据不得跨集合，防止近重复泄漏；
- 每个案例具有 dataset version、case ID 和来源说明。

## 3. Phase 7B：Grader

### 端到端指标

- 任务完成率与受控降级率；
- candidate label accuracy / macro-F1；
- Citation compliance 与 unsupported-claim rate；
- 敏感信息泄漏数；
- confirmed 自动越权数必须恒为 0。

### 步骤级指标

- 工具选择 precision/recall；
- 参数合法率与故障域匹配率；
- 重复失败调用率；
- Evidence 覆盖率、可靠性和归属正确率；
- 无效轮次、总轮次、工具调用数、时延和估算成本。

代码规则 Grader 是强制门禁；模型 Grader 仅评价解释质量，不能覆盖事实、安全和权限规则。人工 Grader 负责 disputed / review_pending 案例。

## 4. Phase 7C：版本比较与发布门禁

- 每次评测记录代码 commit、数据集版本、模型、参数、Prompt hash 和运行环境；
- candidate 与 baseline 在相同变量下比较；
- 输出总体指标、分故障域指标、逐案例 diff 和失败归因；
- P0 安全/权限/confirmed 越权出现一次即阻塞；
- 核心指标不得低于基线容差，改善必须报告置信区间或样本规模；
- 报告进入 Git，但原始敏感输入和真实密钥不得进入仓库。

## 5. Phase 7D：真实模型与人工闭环

- 真实模型只运行脱敏后的受限案例；
- 默认单案例一次调用，不自动重试；
- 记录 token、时延、错误类型和模型版本；
- 与 Fake/规则基线分开报告，不用固定案例满分冒充真实准确率；
- 人工复核结果可以生成新的候选用例，但必须经过去重、脱敏和数据集评审。

## 6. 禁止事项

- 不用 Validation/Test 案例直接调规则；
- 不把 LLM-as-a-Judge 当作安全与事实的最终裁判；
- 不只报告平均分而隐藏失败案例；
- 不因模型超时自动无限重试；
- 不把固定 5 个案例的 100% 表述为生产准确率；
- 不自动把线上数据加入测试集。

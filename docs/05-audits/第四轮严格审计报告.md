# 第四轮严格审计报告

## 1. 审计范围

本轮审计覆盖 Phase 0～8 的运行装配、工具信任边界、数据集协议、真实模型评测、RAG、持久化与评测运营。审计标准不是“测试是否通过”，而是检查测试全绿时仍可出现的安全绕过、血缘失真和能力表述偏差。

审计基线：`7bde31c`；基线全量测试 `1272 passed`。

## 2. 结论摘要

| 等级 | 数量 | 结论 |
|---|---:|---|
| P0 | 1 | 工具失败和自定义工具结果可能把底层异常中的敏感文本回传给 LLM |
| P1 | 4 | 数据集血缘、发布回执完整性、Test 密封探针和真实模型能力表述需要收紧 |
| P2 | 3 | 测试规模、工具重复代码和正式 Runtime 能力范围进入后续治理 |

## 3. P0

### P0-01：工具结果边界未统一脱敏

`failure_result()` 直接保存传入 error；各设备工具与 ToolRegistry 又把 `str(exc)` 拼入该字段。Runner 会把 `result.error` 作为 Tool 消息发回 LLM。若真实 DeviceGateway 抛出包含 URL userinfo、Token 或 password 的异常，敏感信息可在持久化之前进入模型上下文。

修复要求：ToolEvidenceDraft 与 ToolExecutionResult 构造期统一脱敏；Registry 对第三方工具返回值重新构造校验，阻断构造后修改；失败结果不得携带 Evidence；增加“异常 → Registry → Runner → LLMRequest”全链路泄漏反例。

## 4. P1

### P1-01：数据集目录版本和 dataset_name 未绑定

DatasetRegistry 只检查三个 manifest 的 dataset_version 是否相同，没有确认版本目录名与 manifest version 一致，也没有确认三个 split 的 dataset_name 一致。复制或错误命名目录仍可能被加载，削弱版本血缘。

### P1-02：发布回执未绑定实际 Manifest

Phase 8D `release.json` 记录治理 ID 和数量，但没有三个 split Manifest 的哈希或整体内容哈希，也没有公开的回执复验入口。案例文件可由 Manifest 检测，但治理回执与发布内容之间缺少确定性绑定。

### P1-03：固定脚本的 Test 密封结果是常量

Phase 8D 固定脚本输出 `test_set_remains_sealed=true`，但该值不是由实际拒绝访问产生。专项测试覆盖了行为，但脚本报告自身不能作为独立验收证据。

### P1-04：真实模型评测不是完整 Agent Loop 评测

Phase 7D 真实模型入口直接要求模型返回候选标签、工具集合和 Evidence 类型，再由评测器评分；它不执行正式 ToolLoopRunner、真实 DeviceGateway 或实际工具调用。因此当前结果只能称为“受限事实上的结构化诊断决策基线”，不能称为真实端到端 Agent 或设备诊断准确率。

修复要求：代码和文档明确能力口径；真正端到端验证进入 Phase 9，只读真实/高保真设备 Adapter 建成前不得扩大结论。

## 5. P2 与后续风险

### P2-01：正式 Runtime 仅摄像头域且仍为 StaticDeviceGateway + FakeLLM

这是已声明的能力边界，不是当前缺陷，但它是企业接入前的最大差距。Phase 9 应先做 Adapter 能力与安全协议，不能直接放开四域 allowlist。

### P2-02：大量设备工具重复捕获 Exception

统一结果脱敏可修复安全问题，但工具实现仍存在重复模板。暂不进行大规模重构，避免审计修复扩大行为面；Phase 9 可在真实 Adapter 接入时抽取受控调用模板。

### P2-03：1272 个测试不等于 1272 个独立业务能力

其中包含参数化边界、协议守卫和重复域行为。测试数量可证明回归面，不能作为诊断准确性指标。后续报告继续以数据集规模、来源构成和真实模型调用数为主。

## 6. 修复验收门槛

- P0 全链路敏感异常不得进入 ToolExecutionResult、Runner messages 或 LLMRequest；
- DatasetRegistry 拒绝目录版本错配和跨 split dataset_name 错配；
- 发布回执能复验 split Manifest 哈希与整体数据集内容哈希；
- Test 密封状态来自真实拒绝访问；
- README、Phase 7/8 总结不把真实模型结构化评测描述为端到端 Agent 评测；
- ruff、专项测试、全量测试和 `git diff --check` 全部通过。

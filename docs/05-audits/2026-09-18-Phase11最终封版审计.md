# 2026-09-18 Phase 11 最终封版审计

## 1. 审计结论

Phase 11 可以按“真实设备最小只读协议链路已验证”封版。项目已经完成从 Simulator
到单台授权 Wi-Fi 真机的 WS-Discovery、ONVIF HTTP Digest、Profile、Stream URI 与
RTSP Digest OPTIONS 闭环；没有证据支持“生产上线”“多厂商兼容”“长期真机稳定”或
“真实诊断准确率”表述。

本轮无未解决 P0/P1。全量回归期间发现两个 P1，并在封版前修复：

1. Device Lab 的动态私网 Stream URI host 被静态 allowlist 拒绝。修复为默认拒绝、
   仅显式允许私网 URI host 重写，且实际连接始终使用受控 `rtsp_probe_host`；公网地址
   仍拒绝。
2. 主、子码流共享 `DEVICE_STREAM` 类型，被证据解析器误判为同类事实冲突。修复为
   先按 `stream_kind` 分区，再在分区内执行可靠性、时间和 payload 冲突解析；规则的
   证据链会透明列出失败码流类型。

## 3. 安全审计

- 真机操作均由用户逐轮明确授权，调用预算在执行前固定；没有自动重试。
- 设备 Adapter 与探针没有写操作；未执行 PTZ、配置、重启、固件或录像修改。
- ONVIF/RTSP 密码只在进程内解析；RTSP 发送 Digest 摘要而非明文密码。
- Git 内容不保存真实 IP、XAddr、Stream URI、Profile Token、challenge、原始响应、
  设备标识或画面。
- 真机报告与 Simulator 报告分开；真实模型 Token 不可得时保持 `null`。
- Device Lab 停止后无容器、进程和运行时凭证残留。
- 用户在交互界面中暴露过临时设备密码；它未进入仓库，但必须由用户在设备端轮换。

## 4. 已验证与未验证边界

### 已验证

- 单台授权消费级 Wi-Fi 摄像头的局域网只读发现与认证；
- DeviceInformation、Profiles、主码流结构、Stream URI 和 RTSP Digest OPTIONS；
- HTTP Digest 与 RTSP 无-qop Digest 的实际兼容；
- Simulator 八类故障、跨来源 Agent Loop 和十轮恢复稳定性；
- 失败不伪造 Evidence、CitationPolicy 与 HumanReview 边界保持有效。

### 未验证

- 第二厂商、第二型号、不同固件和多设备并发；
- 视频解码与真机黑帧内容判断、音频、录像、告警订阅；
- 24/72 小时连续运行、断电重启、Wi-Fi 漫游与弱网长期恢复；
- 公网、NAT 穿透、云平台与生产网络；
- 设备写操作及其回滚；
- 真实用户误报率、诊断准确率和生产 SLA。

## 5. 非阻塞 P2

1. Phase 5 评测脚本的 `--help` 语义应改为只显示帮助，不连接本机 BGE。
2. RTSP Digest 当前只支持设备实测需要的 MD5、`qop=auth` 与无-qop；未覆盖 SHA-256
   或厂商私有算法。
3. 真机验证为短时、单设备协议闭环；长期与多厂商证据仍为空。

## 6. 封版决定

停止增加 Phase 和故障域。后续仅允许：安全缺陷修复、真机兼容修复、文档纠错、
面试材料与教学材料整理。对外统一表述为：

> 项目完成高保真 Simulator 的十轮稳定门禁，并在一台授权 Wi-Fi 摄像头上完成
> ONVIF/RTSP Digest 最小只读协议闭环；未宣称生产上线或多厂商长期稳定。

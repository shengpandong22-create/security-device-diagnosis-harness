## 3. 逐项修复细节

### 3.1 授权只读快照（`3935b76`）

- **反例（实测）**：`build_runtime_container(memory)` 后调用 `runtime.authorization.rotate(...)`，
  观察 `budget_state.total_calls_consumed` 由 `1` 回到 `0`、`batch_index` 由 `0` 变 `1`，
  即公开调用方可替换 manifest 并重置预算。
- **根因**：`RuntimeContainer.authorization` 字段直接持有原始 `DeviceAuthorizationSession`。
- **修复**：新增 `RuntimeAuthorizationView` 只读快照，仅暴露
  `session_id` / `manifest` / `budget_state` / `batch_index` / `closed`；原始会话只存在于模块级
  弱引用表，容器经受控辅助函数 `_close_authorization_session()` 在 `close()` 时关闭；Gateway 仍共享
  同一强制预算载体。
- **修改文件**：`src/security_diagnosis_harness/runtime.py`、`tests/runtime/test_runtime_container.py`
- **局部测试**：`tests/runtime/test_runtime_container.py` 24 passed；
  `tests/runtime` + `tests/test_device_authorization.py` 216 passed。
- **测试证明**：公开视图无 `rotate/authorize/close`，`object.__getattribute__(view, "_session")` 失败；
  Gateway 真实调用后预算计数递增且无法被重置；容器关闭后旧视图仍不能重置预算。

### 3.2 超时协作取消（`1909bac`）

- **反例（实测）**：复现旧 `_within_deadline` 语义的脚本显示，返回 `TimeoutError` 后副作用计数器
  仍增加 `28` 次，且 worker 线程存活。
- **根因**：旧实现把操作放入 daemon 线程后仅 `join(timeout)`，超时即抛错，worker 无任何取消信号。
- **修复**：引入运行级协作取消令牌 `RunCancellation` 与 `current_cancellation()` 契约；`_within_deadline`
  在超时后先 `cancel()`，再以 `_CANCELLATION_GRACE_SECONDS` **有限等待** worker 协作退出，随后抛出超时；
  迟到结果一律丢弃。未加大 timeout、未使用无界 join、未吞迟到结果、未使用 `Future.cancel()`。
- **修改文件**：`src/security_diagnosis_harness/agent/runner.py`、`tests/agent/test_runner.py`
- **局部测试**：`tests/agent/test_runner.py` 23 passed。
- **测试证明**：模型路径与工具路径两条用例均断言返回后副作用计数不变、无 Evidence、只调用一次
  （无重试）、无 `tool-loop-budget-worker` 遗留线程；另有 `current_cancellation()` 在 Runner 外为 `None`。

### 3.3 可持久化可信 Head（`0200523`）

- **反例**：原有实现只有 `InMemoryHistoryHeadStore`，进程重启后 Head 缺失，历史必然加载失败。
- **根因**：可信锚只存在于进程内存。
- **修复**：新增 `FileHistoryHeadStore`，把不透明 HMAC 标签原子落盘到独立文件；显式声明单机文件系统
  信任边界；完整性密钥仅在内存注入。
- **修改文件**：`src/security_diagnosis_harness/evaluation/history.py`、
  `src/security_diagnosis_harness/evaluation/__init__.py`、`tests/evaluation/test_evaluation_history.py`
- **局部测试**：`tests/evaluation/test_evaluation_history.py` 33 passed。
- **测试证明**：重启加载成功；回滚 / 截尾 / Head 缺失 / Head 篡改分别以稳定错误拒绝；
  历史文件与 Head 文件都不含完整性密钥，Head 值均为 64 位十六进制。

### 3.4 历史并发与崩溃恢复（`32a5c4b`）

- **反例（实测）**：两个实例并发 `append`（放大竞态窗口）后只剩 2 条记录（丢失一条），
  并伴随固定 `history.json.tmp` 的 `PermissionError`。
- **根因**：`load → write tmp → replace → save head` 无互斥，且所有写者共用同一临时文件名。
- **修复**：整个 `load-modify-write` 周期置于同机排它锁下（进程内按路径共享 `RLock` + 跨进程
  OS 文件锁）；staging 改为确定性 `.pending`；发布顺序固定为 **stage → 提交 head → 原子替换**，
  并新增 `_recover_pending()` 在加载期完成或丢弃被中断的发布。
- **修改文件**：`src/security_diagnosis_harness/evaluation/history.py`、`tests/evaluation/test_evaluation_history.py`
- **局部测试**：`tests/evaluation/test_evaluation_history.py` 36 passed；`tests/evaluation` +
  `tests/test_eval_phase8_history.py` + `tests/test_eval_phase8_release.py` 299 passed。
- **测试证明**：两实例并发 append 三条记录全部存在、两条 candidate 的 `baseline_run_id` 均指向
  已入历史的 baseline 且 Gate 结论合法；无 `.pending` / `.tmp` 残留；两种崩溃点分别验证恢复与丢弃。

### 3.5 真实模型响应 fail closed（`6ef137b`）

- **反例**：`usage` 缺失时 `int(usage.get("prompt_tokens", 0))` 静默退化为 0 token / 0 cost；
  响应体无任何字节上限。
- **根因**：token 提取使用带默认值的宽松读取，且未在解析前做大小检查。
- **修复**：`_require_usage_tokens()` 强校验 `usage`（映射 + 两个非负整数字段，拒绝 bool/float/str），
  缺失或非法分别报 `missing_usage` / `invalid_usage`；新增 `max_response_bytes`、`max_content_chars`
  并在解析前检查；受控错误改用 `from None`，不把 httpx / JSON 原始异常挂到因果链。
- **修改文件**：`src/security_diagnosis_harness/evaluation/real_model.py`、`tests/evaluation/test_real_model_eval.py`
- **局部测试**：`tests/evaluation/test_real_model_eval.py` + `test_real_model_baseline.py` +
  `test_real_model_taxonomy.py` 63 passed。
- **测试证明**：8 组非法 usage 全部 fail closed 且只发 1 次请求；超限报 `response_too_large` /
  `content_too_large`；错误文本与因果链都不含 endpoint / 正文；合法 usage 正常解析。

### 3.6 BGE Adapter 边界（`cee0077`）

- **反例**：原适配器接受任意 `base_url`、无限批量与超长文本、无响应上限、向量只校验长度。
- **根因**：构造与调用路径都缺少边界校验。
- **修复**：host/scheme/port 三重 allowlist（默认仅本机 `127.0.0.1:18080`）、禁止
  userinfo/query/fragment；批量 / 单条 / 总字符 / 响应字节上限；向量拒绝 NaN、Infinity、字符串、
  布尔与错误长度，`index` 必须恰好覆盖 `0..n-1`；新增 `BgeEmbeddingError`、`close()` 与上下文管理器。
- **修改文件**：`src/security_diagnosis_harness/adapters/embedding/http_bge.py`、
  `src/security_diagnosis_harness/adapters/embedding/__init__.py`、`tests/adapters/test_embedding_adapters.py`
- **局部测试**：`tests/adapters/test_embedding_adapters.py` 44 passed；`tests/adapters` 356 passed。
- **测试证明**：8 组非法 endpoint、6 组非法边界参数、3 组输入越界、13 组非法向量/索引全部被拒；
  错误文本不含 endpoint；注入 client 不被适配器关闭；守卫测试断言 `runtime.py` 不引用 BGE 适配器。
- **边界**：所有 HTTP 测试使用 `httpx.MockTransport`，**未访问真实 BGE**。

### 11.7 仍需保留的已知限制（不得声称已闭环）

1. **取消是协作式的，不是强制终止**：Python 无法抢占式终止正在运行的线程。严格模式的准入闸门
   保证"未声明的参与者不会被执行"，但对**已声明却违约**的实现，Runner 只能在有限宽限后返回并把
   运行标记为 `cancellation_confirmed=False`；该次运行的迟到副作用无法被阻止。
2. **绕过准入闸门的直接调用不受保护**：直接调用私有 `_within_deadline` 仍只是"放弃等待"。
   这不是公开契约，但也**不是**可依赖的安全边界。
3. **BGE 与真实 LLM 仍未接入正式 Runtime**；Head 的信任模型仍是**单机文件系统**，不提供分布式
   一致性或抗内部篡改保证。
4. **`FileHistoryHeadStore` 与历史文档同名是配置错误**：若把 Head 文件路径配成历史文档路径，
   两者语义会互相破坏；本轮未新增该场景的守卫（属于配置契约，未在本轮范围内）。

## 12. 2026-10-01 Runner 最终复核修订

独立复核证明 `44409c9` 的严格模式仍可被“声明 `cancellation_aware=True`、实际不检查取消”
的参与者击穿；`FakeLLM(responder=...)` 与继承 `BaseTool` 的网关工具都能形成该反例。因此第
11.2 节中 Runner 的“闭环”结论撤回，以本节为准。

最终实现删除 Runner 的后台 worker，改为同步执行并在操作返回后检查 deadline。越时结果不进入
Evidence 或结论，且 Runner 返回时操作已经结束。该方案不声称抢占式中止任意 Python 代码；永不
返回的底层实现会阻塞调用方，正式 Adapter 必须依靠自身 I/O timeout 收敛。

`cancellation_confirmed` 已进入 `RunDiagnosisResult` 与 API 响应；应用服务在任何 Evidence 落库前
强制拒绝 `False`，从而形成 Runner → Application → API 的治理闭环。
